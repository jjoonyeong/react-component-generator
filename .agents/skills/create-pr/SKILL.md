# Create PR

## 위임 필수

- 메인 에이전트는 PR 작성·생성을 직접 수행하지 않고 전담 서브 에이전트에 위임한다. 메인은 작업 맥락 전달, 결과 확인, 사용자 보고를 맡는다.
- 위임할 때 이 `SKILL.md`의 절대 경로, 저장소 경로, 사용자 요청과 기존 승인 범위, 알려진 base/head, 관련 검증 결과를 전달한다. 서브 에이전트가 이 스킬과 저장소 규칙을 읽게 한다.
- **이미 PR 실행 담당으로 위임받은 서브 에이전트는 다시 위임하지 않고 직접 수행한다.** 위임 여부는 현재 역할과 전달된 작업으로 판단한다.
- 메인에게 위임 도구가 없으면 직접 생성으로 대체하지 않는다. 서브 에이전트 실행이 불가능하다는 제약과 남은 작업을 알린다.

## 실행 담당의 작업

1. 저장소의 `AGENTS.md`, PR 템플릿과 기여 규칙을 확인한다. Git 상태, 원격 저장소, 현재 브랜치, 대상 base와 head를 확인하고 실제 커밋·차이를 읽는다. base를 무조건 `main`으로 가정하지 않는다. 확정할 수 없는 대상만 사용자에게 묻는다.
2. 생성 대상 커밋에 무엇이 포함되는지 확인한다. 커밋되지 않은 변경을 PR에 포함된 것처럼 설명하지 않는다. 요청에 커밋 권한이 없다면 임의로 커밋하거나 변경을 버리지 않고 필요한 선행 작업을 알린다.
3. 같은 저장소의 동일 head/base에 열린 PR이 있는지 조회한다. 있으면 중복 생성하지 않고 URL을 반환한다. 기존 PR의 본문 수정은 요청 범위에 포함될 때만 한다.
4. 변경의 문제와 결과를 먼저 설명하는 제목·본문을 작성한다. 최종 diff를 기준으로 범위를 맞추고, 실제 수행한 검증과 미수행 이유·한계를 구분한다. 기존 검증 결과가 최종 변경에 유효하면 재사용한다. 규모에 맞게 짧게 쓰고 확인하지 않은 성공, 이슈 번호, 효과를 만들어내지 않는다.
5. 본문 초안만 요청받았다면 작성한 내용을 반환한다. 실제 PR 생성 요청은 해당 작업에 필요한 일반 브랜치 push와 PR 생성을 포함하는 것으로 처리하며, 이미 승인된 작업에 재확인을 요구하지 않는다. 별도 요청 없이 force push, 이력 재작성, 병합, 리뷰어 지정, 자동 병합 설정을 하지 않는다.
6. GitHub 연결 도구가 충분하면 우선 사용하고, 필요하면 인증된 `gh`를 사용한다. 대상 저장소·base·head를 명시하고 필요한 경우 일반 push 후 생성한다. `gh`로 다중행 본문을 전달할 때는 UTF-8 임시 파일과 `--body-file`을 사용한다. 본문을 셸 코드로 보간하지 않는다.
7. 생성 요청의 응답이 실패하거나 불명확하면 먼저 원격 PR 상태를 다시 조회한다. 생성 여부를 확인하기 전에는 재전송하지 않는다. 인증·권한 오류는 반복 재시도하지 않고 해결에 필요한 정보를 보고한다.
8. 최종 PR의 URL, base/head, 제목·본문을 조회해 의도한 결과인지 확인한다. 메인에 URL, 변경 요약, 검증 결과와 남은 제약을 전달한다. 초안만 작성했다면 원격 생성하지 않았음을 명확히 한다.

## 본문 템플릿

기본은 **하나의 PR 본문에 한국어 다음 영어를 함께 포함**한다. 두 언어가 같은 범위·검증 사실을 전달하도록 한다.

- 기본 양언어 본문을 작성할 때 아래 두 파일을 모두 읽고 순서대로 결합한다.
- 한국어만 명시적으로 요청되면 [국문 템플릿](references/pr-body.ko.md)만 읽는다.
- 영어만 명시적으로 요청되면 [영문 템플릿](references/pr-body.en.md)만 읽는다.

사용자가 지정한 언어·형식과 저장소의 필수 템플릿을 우선한다. 저장소 형식과 양립하면 그 구조 안에 양언어 내용을 넣는다. 관련 없는 선택 항목과 안내 주석은 완성된 본문에서 제거하고, 단순 변경은 요약과 검증 정도로 줄인다. 제목은 사용자 또는 저장소 언어 관례를 따른다.
