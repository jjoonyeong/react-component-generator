# Codex hooks

프로젝트 훅 정의는 `../hooks.json`, 스크립트와 테스트는 이 디렉토리에서 관리한다. Node.js와 Bun이 필요하다. Git 훅은 설치하지 않는다.

## 활성화

신뢰된 프로젝트의 새 Codex 세션에서 훅을 검토하고 신뢰한다. 데스크톱 앱의 **Review hooks / Settings > Hooks**, CLI의 `/hooks`에서 두 명령을 확인한다. 새로 추가하거나 정의를 변경한 훅은 신뢰하기 전까지 실행되지 않는다. 기존 `.codex/config.toml`의 `project-safe` 권한 프로필을 유지한다.

## 커밋 보호

`commit-protection.mjs`는 동기 `PreToolUse` 훅이다. 명령에 `git … commit`이 있으면 저장소 루트에서 `bun --no-env-file run test`로 전체 훅 테스트와 Vitest 테스트를 실행한다. 통과 결과를 캐시하지 않는다. Bun의 환경 파일 자동 로딩을 끄고, Vite도 test 모드에서 환경 파일을 로드하지 않는다.

- 테스트가 모두 통과해야 커밋 명령을 허용한다.
- 실패, 런타임 부재, 실행 오류, 240초 제한 초과는 명시적 `deny`를 반환한다.
- 실패하면 임시 디렉토리에 세션·턴별 차단 표시를 남기고, 해당 턴의 후속 도구 실행도 거부한다. 모델에 실패를 보고하고 중단하도록 전달한다. 새 사용자 메시지의 새 턴에서는 수정과 재검증을 진행할 수 있다.
- 커밋은 별도의 `git commit …` 명령으로 실행한다. 복합 명령, 셸 래퍼, 전역 Git 옵션은 거부한다. 셸 제어 문자가 들어간 커밋 메시지는 `git commit -F 파일`로 전달한다.

다른 터미널에서의 커밋, 파일 내부에 숨긴 간접 명령, 이미 실행 중인 프로세스와 훅을 거치지 않는 도구까지 차단하는 OS 보안 경계는 아니다. Codex 자체의 훅 시작 오류·외부 타임아웃은 도구 실행을 허용할 수 있다. 이 훅은 에이전트 프로세스를 강제 종료하지 않는다.

## TDD 리마인더

`tdd-reminder.mjs`는 `PreToolUse`에서 `.ts`·`.tsx` 대상 패치의 생성·수정·삭제·이동 경로와 파일 쓰기 도구의 경로를 확인한다. 셸 명령은 경로가 명시된 경우 보수적으로 감지하므로 읽기 명령에도 알림이 나올 수 있다. 변수나 별도 스크립트에 숨긴 대상 경로는 알아내지 않는다.

대상 작업이면 루트 `AGENTS.md`의 현재 `# TDD Rule` 섹션만 읽고 `hookSpecificOutput.additionalContext`로 도구 실행 전에 에이전트에게 전달한다. 적용 대상 여부, 실패 테스트의 선행 실행, 하위 `AGENTS.md` 우선 적용을 확인하도록 지시한다. 알림은 TDD 준수를 자동으로 증명하거나 수정 자체를 차단하지 않는다. 규칙을 읽지 못하면 수동 확인 경고를 반환한다.

## 검증

프로젝트 루트에서 `bun --no-env-file run test`를 실행한다. 동작 변경은 실패 테스트 확인 후 구현한다.

공식 동작 및 신뢰 절차: [OpenAI Hooks 문서](https://learn.chatgpt.com/docs/hooks).
